# 仿生鱼 STM32F103C8T6 控制代码生成项目提示词

你是一名熟悉 STM32F1、HAL/CubeMX、嵌入式通信、运动控制和 SSD1306 OLED UI 的高级嵌入式工程师。请基于下述真实硬件连接，为 STM32F103C8T6 生成一个结构清晰、可编译、便于移植和调试的仿生鱼控制工程。

## 一、硬件连接（必须严格遵守）

| 模块 | 接口/信号 | STM32 引脚 | 要求 |
| --- | --- | --- | --- |
| TB6612—电机端口1 | `PWMA` | `PA0` | 驱动 42 步进电机；慢速 60 RPM、快速 100 RPM |
| TB6612—电机端口1 | `PWMB` | `PA1` | 预留/第二路 PWM，不得与 PA0 混淆 |
| TB6612—电机端口1 | `AIN1`、`AIN2` | `PB12`、`PB13` | 电机方向/相位控制 |
| TB6612—电机端口1 | `BIN1`、`BIN2` | `PB14`、`PB15` | 第二 H 桥控制信号，按实际驱动方案使用 |
| 电机端口1 | `M1+`、`M1-` | TB6612 输出 | 接 42 步进电机 |
| 电机端口2 | `M2+`、`M2-` | TB6612 输出 | 接 N20 减速电机，用于抽吸水 |
| 舵机端口1 | `SIG` | `PA6` | IP65 防水舵机，目标偏转角左 30°/右 30° |
| OLED SSD1306 | `SCL`、`SDA` | `PB8`、`PB9` | 软件 I²C；`VCC=+3.3V`、`GND=GND` |
| JY61P | `SCL`、`SDA` | `PB6`、`PB7` | 软件模拟 I²C；`VCC1=+5V`、`GND1=GND` |
| JY61P | `RX`、`TX` | 独立 U3 两针接口 | 当前原理图未连接 STM32，不得将其误分配给 STM32 UART |
| ESP-01S | `RXD`、`TXD` | `PA2`、`PA3` | USART2 交叉收发；`VCC=+3.3V`、`GND=GND` |
| CH340N | `RX`、`TX` | `PB10`、`PB11` | USART3，115200 baud，用于电脑调试 |

补充：按键 1/2/3 分别为 `PB0/PB1/PA8`；运行指示灯为 `PC13`；SWD 为 `PA13/PA14`；外部晶振为 `PD0/PD1`。所有模块必须共地，外部输入不得超过 3.3 V。

### 重要硬件边界

TB6612 通常是双路直流电机 H 桥驱动器，并非标准步进电机 STEP/DIR 驱动器。代码生成前必须检查 42 步进电机的线圈数量、TB6612 实际接法和换相方式；不得凭空生成不存在的 STEP/DIR 引脚。若当前接线无法实现可靠步进控制，必须在文档和代码注释中明确风险，并将换相表、PWM 频率、步进角、减速比等做成可配置参数，禁止隐瞒硬件限制。

## 二、功能目标

1. STM32 为唯一主控，负责电机、舵机、OLED、JY61P、ESP-01S 和调试串口。
2. 电机端口1驱动 42 步进电机，提供 60 RPM 慢速和 100 RPM 快速两档，默认持续单方向旋转；支持停止、启动和速度切换。
3. 电机端口2驱动 N20 减速电机，支持正转、反转、停止和 PWM 调速，用于抽吸水。
4. 舵机端口1控制 IP65 舵机偏转，支持左 30°、中位 0°、右 30°，并限制角度在安全范围内。
5. 通过 USART3/CH340N 以 115200-8-N-1 向电脑周期发送实时调试信息：步进电机目标/实际速度、N20 方向和 PWM、舵机角度、JY61P 姿态角、ESP/安卓连接状态、故障码。
6. OLED 使用 SSD1306 驱动，并移植 `oled-ui-astra`（https://github.com/dcfsswindy/oled-ui-astra）实现非阻塞、流畅刷新。屏幕实时显示：两路电机状态、舵机角度、姿态角（滚转/俯仰/偏航）、上位机连接状态和故障提示。
7. ESP-01S 负责与安卓上位机建立通信；STM32 通过 USART2 接收控制帧并执行，必要时回传状态。不得把 ESP 的未接出引脚（RST/EN/IO0/IO2）当作可控 GPIO。
8. JY61P 必须使用 PB6/PB7 软件 I²C 读取姿态数据，完成设备初始化、数据校验、超时和异常恢复。

## 三、上位机通信协议（先定义，后实现）

采用 ASCII、以换行结尾的帧格式，便于安卓 APK 和串口调试：

### 控制帧：安卓 → ESP → STM32

```text
<CMD,seq=12,move=F,turn=R,step_speed=60,n20_dir=REV,n20_pwm=65,servo=30>\n
```

字段约定：

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `CMD` | 固定 | 控制帧类型 |
| `seq` | 0~65535 | 帧序号，检测丢包/重复 |
| `move` | `F/R/S` | 前进/后退/停止；当前步进电机默认只允许单方向时，`R` 应拒绝并返回错误 |
| `turn` | `L/R/C` | 左转/右转/直行 |
| `step_speed` | `60/100` | 步进电机慢速/快速 RPM |
| `n20_dir` | `FWD/REV/STOP` | N20 正转/反转/停止 |
| `n20_pwm` | `0~100` | N20 占空比百分比 |
| `servo` | `-30~30` | 舵机相对中位角，负值左转、正值右转 |

### 状态帧：STM32 → ESP/CH340N

```text
<STA,seq=12,link=1,step_rpm=60,n20_dir=REV,n20_pwm=65,servo=30,roll=1.2,pitch=-2.4,yaw=85.7,err=0>\n
```

必须实现：帧解析、字段范围校验、校验失败应答、未知字段忽略、通信超时安全策略。ESP/上位机超过可配置超时时间未收到有效控制帧时，电机进入安全状态（至少停止 N20，步进电机按项目安全策略处理），舵机回中或保持由配置决定。

## 四、软件架构要求

- 使用 HAL/CubeMX 风格工程，按 `bsp`、`drivers`、`app`、`protocol`、`ui`、`control` 分层，避免所有逻辑堆在 `main.c`。
- 中断/DMA 仅做收发和置位，解析、控制计算和 OLED 刷新放在主循环或 RTOS 任务中；严禁在中断中阻塞延时。
- 提供统一的毫秒时基、环形缓冲区、超时检测、状态机和故障码。
- 所有 PWM 频率、定时器分频、舵机脉宽、I²C 时序、姿态刷新周期、串口帧超时均使用宏或配置结构体集中管理。
- 对电机换相、方向互锁、PWM 限幅、舵机角度限幅和通信失联保护添加充分注释。
- 不得使用动态内存；避免阻塞式 `HAL_Delay` 影响控制和 UI 流畅度。

## 五、代码验收与交付物

生成代码后必须逐项审查并修正：

1. 编译检查：无未定义引脚、外设实例、宏、类型或链接错误。
2. 引脚核对：代码中的每个 GPIO/UART/PWM/I²C 引脚必须与本提示词一致，不得出现编码器、STEP/DIR 等虚构接口。
3. 功能检查：两档步进速度、N20 正反转/PWM、舵机 ±30°、JY61P 软件 I²C、OLED Astra UI、ESP 通信、CH340N 调试输出均有对应实现或明确的硬件限制说明。
4. 安全检查：通信超时、非法字段、姿态读取失败、I²C 卡死、PWM 越界和电机方向切换均有保护。
5. 注释审查：关键状态机、协议字段、换相逻辑、定时器计算和硬件限制必须有中文注释；删除无效、重复和与实际硬件不符的代码。
6. 输出以下文档：
   - `README.md`：编译、烧录、接线和运行说明；
   - `通信协议.md`：控制帧/状态帧字段、示例、错误码和超时策略；
   - `硬件引脚与驱动说明.md`：实际引脚、外设初始化和 TB6612/步进电机兼容性说明；
   - `验收检查清单.md`：逐项列出已完成、未完成、风险和建议实测项目。

最终输出必须包含：工程目录结构、关键源文件、编译配置、协议说明、已知限制和验收结果。对无法从原理图确认的参数必须明确标注“待实测/待确认”，不得自行编造。
