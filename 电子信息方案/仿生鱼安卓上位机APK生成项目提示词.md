# 仿生鱼安卓上位机 APK 生成项目提示词

你是一名资深 Android 工程师和交互设计师。请生成一个运行在 Android 手机上的仿生鱼控制 APK，用于发现、连接和控制搭载 STM32F103C8T6 + ESP-01S 的仿生鱼，并实时显示鱼体状态。

## 一、通信前提与硬件边界

1. STM32 通过 USART2（`PA2/PA3`）连接 ESP-01S：STM32 `PA2` 接 ESP `RXD`，STM32 `PA3` 接 ESP `TXD`。
2. ESP-01S 通常是 2.4GHz Wi-Fi 模块，不默认支持蓝牙。APK 必须将传输层抽象为 `Transport` 接口，并分别预留 Wi-Fi（TCP/UDP）和 Bluetooth Classic/BLE 实现；只有检测到实际蓝牙硬件时才显示蓝牙入口，不得把 ESP-01S 伪装成蓝牙设备。
3. 连接方式、IP/端口、蓝牙 UUID、配网流程等不能擅自编造，应集中在配置项中，并在 README 中标明待实测参数。
4. APK 不直接控制 STM32 GPIO，只发送协议帧；所有电机、舵机和姿态数据由 STM32 采集/执行。

## 二、必须实现的功能

### 设备发现与连接

- 扫描周围可用设备或局域网内的 ESP-01S 服务。
- 显示设备名称、地址/IP、信号强度、发现时间和连接状态。
- 支持连接、断开、重连、取消扫描；连接中显示进度和超时原因。
- 首次连接后保存用户主动选择的设备，但不得静默连接陌生设备。
- 连接成功后发送握手帧，验证协议版本和设备类型；握手失败显示可操作错误。
- 显示连接状态：未连接、扫描中、连接中、已连接、失联、重连中。

### 仿生鱼控制

- 提供前进、后退（若固件允许）、停止、左转、右转、直行控制。
- 提供步进电机速度档位：慢速 `60 RPM`、快速 `100 RPM`。
- 提供 N20 抽吸电机：正转、反转、停止和 `0~100%` 速度滑杆。
- 提供舵机角度：左 `-30°`、中位 `0°`、右 `+30°`；输入必须限幅。
- 停止按钮必须醒目，支持松手即停或显式停止两种模式，并与协议字段一致。
- 连接断开、控制页退出或应用进入后台时，按配置发送安全停止帧；发送失败必须提示。

### 实时状态回传

显示 STM32 回传的：步进电机目标/实际 RPM、N20 方向和 PWM、舵机角度、JY61P 的滚转/俯仰/偏航、上位机链路状态、协议延迟、最后更新时间和故障码。

提供“控制”与“状态/调试”两个主视图。状态数值应带单位、更新时间和数据有效性标记；数据超时显示“数据过期”，不得继续显示为实时值。

## 三、通信协议（必须按此实现）

采用 UTF-8/ASCII 文本帧，以 `\\n` 结束；解析器必须支持粘包、拆包、非法字段、未知字段和校验失败。

### 控制帧：APK → ESP → STM32

```text
<CMD,seq=12,move=F,turn=L,step_speed=60,n20_dir=REV,n20_pwm=65,servo=30>\\n
```

字段：`seq` 为 0~65535 序号；`move=F/R/S` 表示前进/后退/停止；`turn=L/R/C` 表示左/右/直行；`step_speed=60/100`；`n20_dir=FWD/REV/STOP`；`n20_pwm=0~100`；`servo=-30~30`。

### 状态帧：STM32 → ESP → APK

```text
<STA,seq=12,link=1,step_rpm=60,n20_dir=REV,n20_pwm=65,servo=30,roll=1.2,pitch=-2.4,yaw=85.7,err=0>\\n
```

实现协议版本、握手、心跳、应答、错误码、序号去重、发送队列和超时重连。默认控制帧发送周期、心跳周期和失联超时必须可配置；不要在 UI 线程阻塞等待网络。

## 四、UI 设计要求（从 UI设计RP.md 提炼）

- 先建立设计令牌和可复用组件，再实现页面；组件至少包括按钮、方向控制、滑杆、状态徽标、设备列表、提示条、对话框、加载和空状态。
- 以功能优先、简约清晰为原则，避免大面积装饰、无意义插画和复杂层级；控制页打开后应能快速看到连接状态和停止控制。
- 移动优先，适配 320px 以上手机、平板横竖屏；控件不得重叠或因文字变长而溢出。
- 触控目标不小于 44dp；提供清晰的按下、禁用、焦点、加载、错误和成功状态；关键控制提供无障碍标签和 TalkBack 描述。
- 正常文本对比度至少 4.5:1，大字号至少 3:1；支持系统字体放大至 200% 和减少动态效果设置。
- 使用 4dp 基础间距（常用 4/8/12/16/24/32dp），字体层级清楚；颜色使用主色、辅助色及 success/warning/error/info 语义色，不依赖颜色单独传达状态。
- 支持浅色/深色主题，图标与文字组合表达关键动作；危险操作（停止、断开、恢复出厂）必须有明确确认或撤销机制。
- 动画只用于连接、刷新和状态变化反馈，必须非阻塞；尊重“减少动态效果”系统偏好。

## 五、工程实现要求

- 使用 Kotlin、Jetpack Compose、Material 3、单 Activity + Navigation；采用 MVVM 或 Clean Architecture。
- 分层实现 `transport`、`protocol`、`device`、`control`、`telemetry`、`ui`、`settings`，网络/蓝牙 I/O、解析和重连逻辑不得写在 Composable 中。
- 使用协程、Flow/StateFlow 管理连接状态和实时数据；禁止在主线程执行扫描、网络读写或阻塞延时。
- 权限按 Android 版本动态申请（附近设备、位置/Wi-Fi 等），仅在实际功能需要时申请，并解释用途。
- 提供模拟设备/回放模式，使无硬件时也能验证控制页、协议解析和状态图表；模拟器与真实传输共用同一协议层。
- 记录必要的本地日志，用户可导出最近一段通信日志；不得默认上传用户数据。

## 六、验收与交付物

生成代码后必须完成：

1. 编译、静态检查、单元测试和基础 UI 测试；修复所有错误和警告中与功能相关的问题。
2. 测试设备发现、连接/断开/重连、握手、心跳、粘包拆包、非法帧、超时、后台切换和失联安全停止。
3. 核对所有协议字段、范围和单位；不得出现与 STM32 实际协议不一致的字段或虚构蓝牙能力。
4. 在模拟设备模式验证前进、左右转、两档速度、N20 正反转/PWM、舵机 ±30° 和实时状态显示。
5. 检查深色模式、字体放大 200%、TalkBack、触控目标、横竖屏和减少动态效果。
6. 输出以下文档：
   - `README.md`：构建、签名、权限、连接方式和实机测试步骤；
   - `通信协议.md`：控制帧/状态帧、握手、心跳、错误码和超时策略；
   - `UI设计与交互说明.md`：页面结构、组件状态、响应式和无障碍规范；
   - `验收检查清单.md`：已完成项、未完成项、实测结果和已知限制。

最终报告必须明确：实际使用的传输方式（Wi-Fi 或蓝牙）、ESP-01S 配置参数来源、未实测项目、风险及下一步硬件联调计划。对无法从现有硬件资料确认的内容必须标注“待确认”，不得自行假设。
