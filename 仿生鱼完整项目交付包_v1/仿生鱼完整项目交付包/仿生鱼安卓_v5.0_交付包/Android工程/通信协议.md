# v0.5.0 双电机通信协议

链路：Android → Wi-Fi TCP → ESP-01S → STM32。保留 V1 ASCII 协议，不增加未经固件支持的 HELLO/PING。本文固件行为来源为用户改造方案；实际板卡版本与动作待联调确认。

## 1. 帧格式

```text
<TYPE,key=value,...>\n
```

`\n` 表示实际 LF 字节 0x0A，接收兼容 CRLF。有效载荷最大 191 字节；流式接收支持粘包、拆包、半帧超时及重新同步。未知字段忽略，重复字段、非法数值、错误结束符等拒收整帧，不提交部分状态。

## 2. 控制 CMD：完整目标

```text
<CMD,seq=12,move=F,turn=L,step_speed=60,servo=-15,m2=R>\n
```

| 字段 | 值 | 语义 |
| --- | --- | --- |
| seq | 0..65535 | 新命令递增，允许回绕；幂等重传保留原序号。 |
| move | F / R / S | M1（370）前进 / 后退 / 停止。 |
| turn | L / R / C | 必须分别对应 servo 负值 / 正值 / 0。 |
| step_speed | 60 / 100 | 旧兼容字段；UI 固定发送 60，不影响配套直流固件占空比。 |
| servo | -15..15 | 目标角度，度；模型越界拒绝，UI 先限幅。 |
| m2 | F / R / S | M2（N20）前进 / 后退 / 停止；新 APK 每帧发送，位于 servo 后。 |

固件兼容的旧 CMD 缺少 m2 时，M2 **停止**，不是维持原方向。M1、M2 和舵机同时构成完整目标；修改一路时必须带上另一路和舵机的期望值。

安全停止（默认回中）：

```text
<CMD,seq=13,move=S,turn=C,step_speed=60,servo=0,m2=S>\n
```

若关闭安全停止回中，两路仍显式 STOP，只保留合法舵角与 turn。单路停止是高优先级完整目标，只把该路设 S；全局急停、默认后台/离页/断开停止为双 S。新安装默认允许两路 R；旧的关闭偏好保留，设置同时约束 M1/M2。

## 3. 状态 STA

```text
<STA,seq=12,link=1,step_rpm=NA,step_est=NA,step_actual=NA,step_on=1,servo=-15,roll=1.2,pitch=-2.4,yaw=85.7,m1=F,m2=R,err=0>\n
```

必填集合保持原 10 项：`seq/link/step_rpm/step_est/step_actual/servo/roll/pitch/yaw/err`。`step_on/m1/m2` 均可选，不因旧固件缺字段拒绝握手。

| 字段 | 接收行为 |
| --- | --- |
| m1 / m2 | F/R/S 转为独立方向；缺失为未知，其它值拒绝整帧。是已下达方向，不是实际机械反馈。 |
| step_on | 只能 0/1；仅表示 M1。缺失时可从旧的已知目标 RPM 推断 M1 运行；不能据此推断 M2 或具体方向。 |
| step_rpm / step_est | NA 或旧数字 0/60/100；NA 保持未知，不能填成 0。 |
| step_actual | NA 或有限数值；新固件没有编码器，不制造实际转速。 |
| servo | 接收单独保留 -30..30 兼容旧状态；**发送仍严格 ±15**，不据接收值扩大操控范围。 |
| roll / pitch / yaw | 有限数字或 NA，单位度；姿态与舵机命令角分开显示。 |
| link / err | link 为 0/1；err 为非负十进制位图。非零 err 是合法 STA，但不意味着硬件健康。 |

## 4. ACK、ERR、握手与时间

```text
<ACK,seq=12,result=OK>\n
<ACK,seq=12,result=DUP>\n
<ERR,seq=12,code=E_RANGE>\n
```

握手发送双停 CMD，要求同序号 ACK（OK/DUP）及 `link=1` 合法 STA。等待过程中每 400 ms 重发同一内容和序号，不添加第二个 ACK 等待器；完成、失败、取消均停止该保活任务。先等 ACK 默认 800 ms，再保留 STA 默认 2000 ms 窗口，不将全过程说成固定 2 秒。

| 参数 | 默认值 |
| --- | ---: |
| 运动目标发送 / 停止保活 | 200 / 500 ms |
| TCP 连接超时 | 5000 ms |
| ACK / 应用失联 / 遥测过期 | 800 / 1000 / 1200 ms |
| 重连间隔 / 最大次数 | 1000 ms / 3 次 |

控制与保活周期可配 50..750 ms；ACK 可配 100..900 ms 且短于失联阈值。周期发送完整 CMD 保活；重连从双停握手开始，不恢复断线前运动。发送与 ACK 等待不阻塞 UI，安全停止优先于普通排队命令。

## 5. 错误与兼容

`E_RANGE`：方向/舵角等非法；`E_DUP_FIELD`：重复字段；格式错误可返回 `E_FORMAT`。其它合法 `E_*` 原样展示。旧固件的 `E_STEP_REVERSE_UNSUPPORTED`、`E_STEPPER_HW_UNCONFIRMED` 仍按错误处理，不能伪报执行成功。

故障位沿用：bit0 链路超时，bit1 ESP RX 丢失，bit2 姿态超时，bit3 IMU I²C，bit4 **旧步进门禁（新双电机不用）**，bit5 UART TX 丢弃，bit6 保留，bit7 OLED I²C，bit8 配置异常；未知位保留显示。bit4 不再拦截新版直流电机 UI。

新 APK 对无 m1/m2 的旧 STA 显示未知；旧固件可能忽略 m2 或拒绝反向，不保证双电机可用。旧 APK 的 ±30° 命令会被 ±15° 新固件拒绝。四向真实硬件兼容矩阵尚未执行；本机仅协议/Mock 回放，不替代烧录版本核对。

应用尽力发停止，链路断开时无法保证送达。用户方案称固件 1000 ms 无有效 CMD 会双停并关闭旧 TCP；实际时间与舵机回中必须板上验证。本次没有改固件/网页，系统级 ±15° 需要配套确认。
