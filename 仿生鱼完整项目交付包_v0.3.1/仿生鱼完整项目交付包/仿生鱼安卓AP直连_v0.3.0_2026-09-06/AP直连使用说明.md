# ESP-01S AP 直连使用说明

## 1. 本次增加了什么

“设备”页新增常驻的“AP 直连 · 仿生鱼热点”入口。无需扫描，手机加入 ESP-01S 热点后，即可建立 TCP 连接，并继续使用原来的步进电机、舵机控制和姿态状态页。普通局域网 TCP/UDP 与模拟设备模式仍保留。

这不是蓝牙模式，也不是 APK 直接控制 STM32 引脚。链路为：

```text
Android TCP 客户端 → ESP-01S SoftAP / TCP 服务器 → USART2 → STM32
                    192.168.4.1:9000             PA2/PA3
```

本版只更新 Android 工程。用户指引称当前 STM32 已完成 AT / `+IPD` 桥接；本次没有重新验证或改写该固件，也没有重新生成 STM32 二进制文件。不要用此前不含 AT / `+IPD` 桥接的旧固件覆盖已联调版本。

## 2. 参数来源与边界

以下初始参数来自用户提供的《AP直连_安卓端修改指引.md》（文内日期 2026-09-06），不是本机连接真实 ESP 测得的参数：

| 配置 | 初始值 | 使用说明 |
| --- | --- | --- |
| 热点名称 | `BionicFish-AP` | 在手机系统 Wi-Fi 设置中选择；若设备端已修改，以实际值为准。 |
| 热点初始密码 | `12345678` | 由用户在系统 Wi-Fi 设置输入；APK 不代替系统保存或提交 Wi-Fi 凭据。 |
| TCP 地址 | `192.168.4.1` | ESP 热点网关；设置页可修改为实际 IPv4 地址。 |
| TCP 端口 | `9000` | 设置页可修改；必须与 ESP 服务器一致。 |
| 桥接方式 | AT 固件 1.7.4 + STM32 AT / `+IPD` | 来自用户指引。透明 TCP 桥只要对手机提供相同 V1 字节流也可兼容，未在本次实测。 |
| USART2 | `115200` 波特率 | 来自用户指引；APK 不配置 MCU 串口。 |
| 状态回传周期 | 约 `200 ms` | 指引中 STM32 配置值，不是 APK 对真实设备的测量结果。 |

默认值集中在 `settings/ApDirectDefaults.kt`。AP 的 SSID、IPv4 和端口独立持久化，不覆盖原来普通局域网的主机/IP 和端口。SSID 必须非空且不超过 32 个 UTF-8 字节；端口范围为 1～65535，地址不能是域名、IPv6、回环或组播地址。

当前 ESP 没有已确认的 UDP 发现应答服务，所以 AP 直连不会调用 UDP 扫描，也不虚构 RSSI 或扫描发现时间。热点名称只是用户设置与连接指引，APK 不读取或验证当前 SSID；即便 V1 握手通过，也不能把它视为设备身份认证。

## 3. 手机上的操作步骤

1. 确认 ESP-01S 与 STM32 供电正常、共地，使用已联调的 TCP 桥接固件。首次试机先卸载机械负载或采用限流供电，并确保能立即断电。
2. 打开 APK 的“设备”页，在 AP 卡片点“打开系统 Wi-Fi 设置”。如果当前已连接其他设备，请先“安全断开”；若正在扫描，请先取消扫描。
3. 在系统设置选择 `BionicFish-AP`，输入初始密码 `12345678`（修改后以实际密码为准）。出现“无互联网连接”时，选择保留/继续使用该 Wi-Fi。不同手机的文字可能不同。
4. 返回 APK，确认 AP 卡片显示 `TCP 192.168.4.1:9000`，点击“连接仿生鱼热点”。无需点“扫描设备”。若实际参数不同，先在“设置”页修改 AP 专用配置并保存。
5. 只有 TCP 连接成功且安全停止探测收到对应 `ACK` 和合法 `STA`，才会显示已连接/握手通过。点“进入控制页”操作。先验证停止和舵机回中，再验证 ±30° 舵机及 60/100 RPM 档位。
6. 控制结束用醒目的停止按钮，再执行“安全断开”。断开、离开控制页和应用进入后台时，沿用现有可配置的安全停止策略。

APK 不自动加入热点，不使用静默配网，也不会在应用重启后静默连接保存的设备。连接成功后保存用户主动选择的 AP 端点；会话中的自动重连仍按既有设置执行，每次重连从安全停止握手开始，不恢复断线前的运动。

## 4. 无互联网热点与移动数据

AP 直连的 TCP Socket 仅使用具有匹配目标 IPv4 非默认本地子网路由的 Wi-Fi 网络，不回退到移动网络、VPN 或系统默认互联网路由。不要求热点具有互联网连通性，不通过进程级网络绑定影响应用的其他连接。普通局域网 TCP/UDP 仍保持原来的传输行为。

网络约束不等同于“已确认热点名”：例如另一台路由器也使用相同网段，仍需用户在系统设置确认所选热点和实际设备。V1 没有设备认证能力。

如果系统断开/切走所使用的 Wi-Fi，APK 关闭本会话 Socket，进入原有失联与重连路径，并重新选择符合要求的 Wi-Fi。该措施不能阻止手机厂商的自动切网行为；请在系统中对热点选择保留连接，必要时关闭“自动切换到更好的网络”。移动数据开启时能否稳定控制仍须在目标手机上实测；不能仅凭模拟器测试宣称已完成。

本方案不读取 SSID、不做系统 Wi-Fi 扫描，不为 AP 入口新增位置或附近设备运行时权限请求。系统 Wi-Fi 的授权与密码输入由系统设置负责。

## 5. 协议与安全时序保持不变

TCP 承载原 V1 ASCII 帧，末尾为实际 LF 字节 `0x0A`，不是反斜杠与字母 `n` 两个字符。AP 模式仍复用原来的粘包/拆包解析、序号去重、ACK/ERR 处理和发送队列。

```text
<CMD,seq=12,move=F,turn=L,step_speed=60,servo=-30>\n
<ACK,seq=12,result=OK>\n
<STA,seq=12,link=1,step_rpm=60,step_est=60,step_actual=NA,servo=-30,roll=1.2,pitch=-2.4,yaw=85.7,err=0>\n
```

握手仍为安全停止 `CMD`，并要求同序号 `ACK` 和有效 `STA`；不新增 `HELLO`、`PING`、UDP 探测报文或未确认的设备类型字段。周期 CMD 兼作保活。已删除 N20 控制；TB6612 的两个 H 桥用于 42 步进的两相线圈。后退仍取决于原有固件门禁，不因 AP 模式新增反转能力。

| 时序/策略 | 原有默认值 | 本次处理 |
| --- | ---: | --- |
| 显式 CMD 的 ACK 超时 | 800 ms | 保持不变。 |
| 应用链路失联超时 | 1000 ms | 保持不变；固件本身也必须有失联停机保护。 |
| 运动控制发送周期 | 200 ms | 保持不变。 |
| 停止保活周期 | 500 ms | 保持不变，不新增心跳帧。 |
| TCP 连接超时 | 5000 ms | 保持不变。 |
| V1 握手超时 | 2000 ms | 保持不变。 |
| 状态过期阈值 | 1200 ms | 保持不变；过期值不得被当作实时值。 |
| 重连间隔 / 次数 | 1000 ms / 最多 3 次 | 保持现有默认值，受保存配置控制。 |

网络停止不是可靠急停。Wi-Fi 已断、ESP 断电或进程被杀死时，停止帧可能无法送达；此时依赖 STM32 自身失联逻辑，实际停机时间和舵机行为须实测确认。安全停发送失败会提示/记录，不能表述为已经确认停机。

## 6. 故障排查

| 现象 | 排查顺序 |
| --- | --- |
| 未找到可用 AP Wi-Fi / 目标不在 Wi-Fi 本地子网 | 打开系统 Wi-Fi 设置，确认已加入正确热点、已获得 IP，检查 AP 地址是否填写正确。SSID 不会由 APK 自动验证。 |
| TCP 超时或连接被拒绝 | 检查 ESP 供电、热点地址、TCP 服务器 9000 端口与桥接初始化；确认手机未切到其他 Wi-Fi。 |
| TCP 已连接但握手失败 | 检查 STM32 USART2 交叉接线、115200 串口与 AT / `+IPD` 桥接，查看是否回传同序号 ACK 和合法 STA；不要仅延长安全时序掩盖故障。 |
| ACK 超时 / 数据过期 | 在状态/调试页区分命令确认与遥测缺失，导出最近通信日志，检查 ESP 队列和 STM32 主循环。 |
| 热点断开或自动重连失败 | 在系统设置重新加入热点并保留无互联网连接，检查自动切网、供电和 ESP TCP 服务；重连不恢复旧运动。 |
| `E_STEPPER_HW_UNCONFIRMED` | AP/TCP 可用不代表步进硬件已验收。先确认双线圈接线、相序、步距角、电流/PWM 与配置门禁，不能由 APK 绕过。 |

## 7. 验收证据与待实测项目

本次没有连接真实 ESP-01S/STM32，也未在用户手机上实测。项目测试覆盖 AP 配置校验、不扫描直连、TCP 路由约束、V1 握手、保存配置、重连安全停止和 AP 页面行为；具体执行结果以交付包《验收检查清单.md》与构建测试报告为准。本文件不把测试定义当作已通过结果。

以下必须由实机联调补齐：

- 实际热点名称/密码/IP/端口与新版 AT / `+IPD` 固件一致；确认手工加入热点成功。
- 目标手机在移动数据开启、热点无互联网时，连接持续稳定且命令确实走 ESP Wi-Fi。
- 首次安全握手成功；约每 200 ms 收到 STA；前进、60/100 RPM、±30° 与停止的实际执行正确。
- 主动断 Wi-Fi、ESP 断电、STM32 重启后显示失联，固件在预定安全时间内停机；重连不自行恢复运动。
- 切后台/离开控制页/手工断开时安全停止成功或明确提示发送失败；200% 字体、TalkBack 和横竖屏在目标手机上检查。
- 同名/同网段其他设备不能被误认为已认证仿生鱼；V1 不加密、不提供强身份认证，需控制热点接入权限。

首次联调建议先仅验证通信和停止，再接入舵机，最后以限流、低负载方式验证步进。保留 STM32 调试日志与 APK 导出日志，以对应序号核对每条命令。
