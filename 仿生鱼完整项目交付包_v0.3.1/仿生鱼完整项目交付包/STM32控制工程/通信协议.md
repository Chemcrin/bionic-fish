# 通信协议

## 1. 基本规则

协议用于安卓上位机经 ESP-01S → USART2 → STM32 发送控制命令，以及 STM32 经 USART2（回 ESP）和 USART3（CH340N）输出确认、错误和状态。它采用可打印 ASCII 与换行分帧，便于 APK 和串口工具调试；不提供加密、鉴权或传输层 CRC。

```text
<TYPE,key=value,key=value,...>\n
```

- 帧尾必须是 `LF`（`\n`）；接收端也接受 `CRLF`。
- 字段值不得包含 `<`、`>`、`,`、`=`、换行或 NUL。帧最大载荷为 `CFG_PROTOCOL_PAYLOAD_MAX-1`，当前为 191 字节。
- 组帧状态机在收到 `<` 后最多等待 `CFG_PROTOCOL_FRAME_TIMEOUT_MS`（当前 250 ms）。超时、超长、不可打印字符或错误 EOL 均丢弃并重新同步。
- UART 中断只接收字节至固定大小环形缓冲；完整帧在主循环解析。任何解析/语义/序号失败都不能造成部分电机或舵机动作。
- 未知但语法正确的 `key=value` 字段忽略，便于版本扩展；已知字段重复或缺失会拒绝整帧。

## 2. 控制帧：安卓 → ESP → STM32

```text
<CMD,seq=12,move=F,turn=R,step_speed=60,servo=30>\n
```

以下五个字段全部必填，顺序可任意：

| 字段 | 取值 | 含义与校验 |
| --- | --- | --- |
| `seq` | `0`~`65535` | 16 位无符号序号，用于重复、乱序和丢包检测。 |
| `move` | `F` / `R` / `S` | 前进、反向、停止。默认 `CFG_STEPPER_UNIDIRECTIONAL=1`，所以 `R` 返回 `E_STEP_REVERSE_UNSUPPORTED`。 |
| `turn` | `L` / `R` / `C` | 左、右、居中语义，必须与 `servo` 符号一致。 |
| `step_speed` | `60` / `100` | 旧协议兼容字段；本轮固定低速运行，两种值均不改变换相周期或 PWM。 |
| `servo` | `-30`~`30` | 相对中位角（度）；负值左、正值右，仍会在驱动层按脉宽限幅。 |

语义约束如下：

- `turn=L` 必须配负 `servo`，`turn=R` 必须配正 `servo`，`turn=C` 必须配 `servo=0`；不一致返回 `E_SEMANTIC`，不会静默选择其中一个。
- `move=S` 仍须携带合法的 `step_speed`，但步进输出进入 coast，状态中的 `step_on=0`。
- 默认 `CFG_STEPPER_DRIVER_ENABLED=1`，`move=F` 以 10% PWM、50 ms 换相周期持续运行。显式设为 0 时拒绝前进并返回 `E_STEPPER_DISABLED`。
- `move=R` 将来只可在显式关闭单方向策略、确认相序和机械方向后使用；当前默认配置不会因收到 `R` 而尝试反向换相。

### 2.1 旧字段兼容性

旧客户端若仍附带 `n20_dir=...`、`n20_pwm=...` 等字段，它们作为未知扩展字段被解析器忽略，不会控制任何硬件，也不会出现在 `STA`。迁移客户端时应删除这些字段；M2 端现在属于步进线圈 B，原 N20 必须物理断开。

### 2.2 序号规则

| 条件 | 动作 |
| --- | --- |
| 首帧，或失联/溢出后新建会话 | 接受，建立序号窗口。 |
| `seq` 与最后成功帧相同且五个控制字段完全相同 | 视为幂等重传，不重复执行，回复 `ACK,DUP` 并刷新保活。 |
| 相同 `seq` 但载荷不同 | 拒绝，`E_SEQ_CONFLICT`。 |
| 模 65536 差值为 1~32767 | 视为新帧，接受；差值大于 1 会记录序号缺口。 |
| 差值为 32768 | 回绕歧义，拒绝，`E_SEQ_AMBIGUOUS`。 |
| 差值大于 32768 | 旧帧/乱序帧，拒绝，`E_SEQ_OLD`。 |

失联或 UART 接收溢出会清除序号窗口，使 ESP/安卓重启后能从新的 `seq` 重新建链。非法帧、语义拒绝帧和旧帧都不能刷新保活。

## 3. 状态帧：STM32 → ESP/CH340N

```text
<STA,seq=12,link=1,step_rpm=NA,step_est=NA,step_actual=NA,step_on=1,servo=30,roll=1.2,pitch=-2.4,yaw=85.7,err=0>\n
```

状态帧按 `CFG_STATUS_PERIOD_MS`（当前 200 ms）周期发送，并在有效命令、失联或错误状态变化后由主循环持续反映最新状态。它可同时送往 ESP 与 CH340N；周期 `STA` 是低优先级，串口队列拥塞时不应阻塞控制或挤掉 `ACK/ERR`。

| 字段 | 含义 |
| --- | --- |
| `seq` | 最近一次成功提交的控制序号；未建链时应结合 `link=0` 判断。 |
| `link` | 最近收到了有效命令/幂等重传则为 1；这只表示应用控制链路新鲜，不证明 ESP Wi-Fi 或安卓连接真实在线。 |
| `step_rpm` | 固定为 `NA`；本轮无 RPM 目标控制。 |
| `step_est` | 固定为 `NA`；未知每转步数，不将换相频率伪报为机械 RPM。 |
| `step_on` | `0` 表示驱动命令停止，`1` 表示持续换相运行；不证明机械轴实际转动。 |
| `step_actual` | 固定为 `NA`，因为本硬件没有编码器、霍尔或外部测速反馈。 |
| `servo` | 最终限幅后的相对中位角命令，不等价于实际舵面反馈角。 |
| `roll` / `pitch` / `yaw` | JY61P 成功读取且有效时的姿态角；读不到/过期时为 `NA`，不能把 0.0 当作有效测量。 |
| `err` | 当前活动故障位图的十进制值；不是最近一次协议错误字符串。 |

### 3.1 `STA.err` 故障位图

| 位 | 十进制值 | 名称 | 含义 |
| ---: | ---: | --- | --- |
| 0 | 1 | `BF_FAULT_LINK_TIMEOUT` | 有效控制帧超时或接收溢出后的强制断链。 |
| 1 | 2 | `BF_FAULT_ESP_RX_LOST` | ESP/USART2 接收缓冲溢出或 ORE 导致字节丢失。 |
| 2 | 4 | `BF_FAULT_IMU_DATA_TIMEOUT` | JY61P 姿态数据过期/不可用。 |
| 3 | 8 | `BF_FAULT_IMU_I2C_RECOVERY_FAILED` | JY61P 软件 I²C 总线恢复失败。 |
| 4 | 16 | `BF_FAULT_STEPPER_DISABLED` | 配置显式禁用步进输出。 |
| 5 | 32 | `BF_FAULT_UART_TX_DROPPED` | UART 发送队列发生丢弃。 |
| 6 | 64 | 预留 | 保留，不用于任何旧电机功能；bit7/bit8 的位置不得前移。 |
| 7 | 128 | `BF_FAULT_OLED_I2C` | OLED 软件 I²C 运行期异常。 |
| 8 | 256 | `BF_FAULT_CONFIGURATION` | 关键配置或实际定时器初始化不一致。 |

多个故障可同时置位并相加，例如 `err=5` 表示链路超时（1）与 IMU 数据超时（4）同时存在。

## 4. ACK、错误帧与错误码

成功新命令与幂等重传的即时应答分别为：

```text
<ACK,seq=12,result=OK>\n
<ACK,seq=12,result=DUP>\n
```

错误帧示例：

```text
<ERR,seq=12,code=E_RANGE>\n
<ERR,seq=NA,code=E_FORMAT>\n
```

| 错误码 | 含义 |
| --- | --- |
| `E_FORMAT` | 定界、不可打印字符、EOL 等帧格式错误。 |
| `E_FRAME_TIMEOUT` | `<` 之后的半帧静默超过配置时间。 |
| `E_TOO_LONG` | 载荷超过固定缓冲限制。 |
| `E_TYPE` | 帧类型不是 `CMD`。 |
| `E_FIELD` / `E_DUP_FIELD` / `E_MISSING_FIELD` | 字段语法错误、已知字段重复或缺少五个必填字段。 |
| `E_RANGE` | 序号、枚举、步进档位或舵机角度越界。 |
| `E_SEMANTIC` | `turn` 与 `servo` 的组合不一致。 |
| `E_SEQ_CONFLICT` / `E_SEQ_OLD` / `E_SEQ_AMBIGUOUS` | 相同序号内容不同、旧帧或回绕歧义。 |
| `E_STEP_REVERSE_UNSUPPORTED` | 默认单方向策略下请求 `move=R`。 |
| `E_STEPPER_DISABLED` | 配置显式禁用步进输出，固件保持两桥 coast。 |
| `E_CONFIGURATION` | 实际定时器配置与 `app_config.h` 不一致等关键配置故障。 |
| `E_RX_OVERFLOW` | UART 环形缓冲溢出/串口错误后，残帧已被丢弃。 |

协议错误用即时 `ERR` 告知；`STA.err` 只描述持续活动的运行期故障，二者不可混用。

## 5. 失联与溢出安全策略

超过 `CFG_LINK_TIMEOUT_MS`（当前 1000 ms）未收到有效命令/幂等重传时：

1. 步进电机始终停止，A/B 两桥均进入 coast，不保持未知相电流；本交付不提供关闭失联停机的开关。
2. 舵机按 `CFG_SERVO_CENTER_ON_LINK_TIMEOUT` 处理；默认值为 1，回到中位。若改为保持，必须通过机械安全实测。
3. `link=0`，置 `BF_FAULT_LINK_TIMEOUT`，USART3 保持周期状态上报；主动关闭旧 TCP 连接，释放单客户端槽位。Android 重连后重新执行 STOP/ACK/STA 握手。

TCP 断开、ESP 重启或发送事务失败也会撤销控制会话。服务端固定配置 `CIPSTO=3` 秒空闲释放；应用已建会话的 1 秒控制超时独立主动关闭连接，不依赖 ESP 对空闲流量的具体判定。

ESP 接收环形缓冲溢出或 UART ORE 更严格：固件立即丢弃残余字节、重置解析器、清除会话和序号窗口、停止步进，并按配置回中舵机；不会等待普通的 1 秒保活超时。之后必须在可用的 TCP 连接上收到一帧完整、通过全部校验的 `CMD` 才能重新建链。连接已断开时 `E_RX_OVERFLOW` 只能通过 USART3 诊断观察，不能承诺已经失效的无线连接仍送达错误帧。

新安卓版本接受 RPM 的 `NA` 和 `step_on`；旧 0.3.1 APK 不支持该状态格式，必须安装本轮新版 APK。新安卓对旧数字 RPM 状态保持读取兼容。

## 6. 示例

默认配置下的低速连续前进请求：

```text
TX <CMD,seq=12,move=F,turn=R,step_speed=60,servo=30>\n
RX <ACK,seq=12,result=OK>\n
```

默认策略下的反向请求：

```text
TX <CMD,seq=13,move=R,turn=C,step_speed=100,servo=0>\n
RX <ERR,seq=13,code=E_STEP_REVERSE_UNSUPPORTED>\n
```

旧客户端携带无效功能字段时，五个必填字段仍正常，旧字段被忽略：

```text
TX <CMD,seq=14,move=S,turn=C,step_speed=60,servo=0,n20_dir=REV,n20_pwm=65>\n
RX <ACK,seq=14,result=OK>\n
```

最后一个示例只说明协议兼容性，不会驱动任何旧的附加电机；M2 端仍只属于步进线圈 B。
