# 硬件引脚与驱动说明

## 1. 当前接线结论

用户于 2026-09-09 确认：实际使用无铭牌的 42 步进电机，已将两组线圈正确连接到 TB6612 的 M1+/M1− 和 M2+/M2−；VM 电机供电为 12 V，报告的线圈电阻约 3 Ω。本工程按这一接线继续开发：A、B 两个 H 桥共同驱动同一颗两相双极步进电机；M2 不再用于 N20 或抽吸机构。这里的 12 V 已确认是供电电压，不能据此认定无铭牌电机的额定电压或电流。

本文件引脚表已与当前 `main.h`、GPIO 和定时器配置核对。旧 `CFG_STEPPER_STOP_ON_LINK_TIMEOUT` 开关已删除，当前失联始终停机。最新配置和实物确认记录维护在本文件。

未经确认的四线电机不能仅用 A 桥驱动，也不能让 B 桥继续接其他负载。若电机不是四线双极类型（例如五线/六线单极、两线执行器或已集成驱动模块），必须停止接线并获得该电机的资料后重新评估；不得套用本工程的双桥换相表。

| 功能 | 信号 | STM32F103C8T6 引脚 | 配置/边界 |
| --- | --- | --- | --- |
| 步进线圈 A PWM | `PWMA` | PA0 | TIM2_CH1 PWM，连接 TB6612 A 桥。 |
| 步进线圈 B PWM | `PWMB` | PA1 | TIM2_CH2 PWM，连接 TB6612 B 桥；不是 PA0 的别名，也不是 STEP。 |
| 线圈 A 相位 | `AIN1` / `AIN2` | PB12 / PB13 | 推挽 GPIO，决定 A 桥电流方向/coast。 |
| 线圈 B 相位 | `BIN1` / `BIN2` | PB14 / PB15 | 推挽 GPIO，决定 B 桥电流方向/coast。 |
| 步进线圈 A 输出 | `M1+` / `M1-` | TB6612 A01/A02 | 只能接同一颗步进电机确认后的线圈 A 两端。 |
| 步进线圈 B 输出 | `M2+` / `M2-` | TB6612 B01/B02 | 只能接同一颗步进电机确认后的线圈 B 两端；原 N20 必须断开。 |
| IP65 舵机 | `SIG` | PA6 | TIM3_CH1，50 Hz 脉冲；实际脉宽和 3.3 V 兼容性待测。 |
| SSD1306 | `SCL` / `SDA` | PB8 / PB9 | 独立 GPIO 开漏软件 I²C，外部上拉仅为 3.3 V。 |
| JY61P | `SCL` / `SDA` | PB6 / PB7 | 独立 GPIO 开漏软件 I²C；电平、地址、协议待确认。 |
| ESP-01S | `RXD` / `TXD` | PA2 / PA3 | USART2 交叉收发：PA2→ESP RXD，ESP TXD→PA3。 |
| CH340N | `RX` / `TX` | PB10 / PB11 | USART3 交叉收发：PB10→CH340 RX，CH340 TX→PB11；当前程序仅输出调试信息，不接收控制命令。 |
| 按键 1/2/3 | - | PB0 / PB1 / PA8 | GPIO 输入；当前配置低有效，仍需板上核对。 |
| 运行指示灯 | - | PC13 | GPIO 输出；当前配置低有效，需实板核对。 |
| SWD | SWDIO / SWCLK | PA13 / PA14 | 保留调试，禁止改作业务 GPIO。 |

PB6/PB7、PB8/PB9 在本工程中均由软件 I²C 驱动，不可再同时由 STM32 硬件 I²C 外设接管。ESP 的 `RST/EN/IO0/IO2` 和 JY61P 的 RX/TX 没有给出 STM32 连线，固件不得虚构这些 GPIO/UART。

## 3. TB6612 与两相双极步进

TB6612FNG 是双全桥直流驱动器，不是 STEP/DIR 步进驱动器。当前接法利用它的两个全桥：

```text
TB6612 A01/A02 (M1) ─── 步进线圈 A
TB6612 B01/B02 (M2) ─── 步进线圈 B
```

`motor_control.c` 使用四拍双相通电全步表。每一拍让两组线圈分别获得正向或反向电流；它没有也不需要虚构 STEP/DIR 信号。线圈对接错或某个线圈极性反向时，电机可能抖动、发热、堵转或反向，必须断电后用万用表找出两组线圈，再通过实测线序或 `CFG_STEPPER_PHASE_REVERSED` 修正。

### 3.1 固定低功率运行

按用户本轮要求，将步进作为普通推进电机使用，只提供前进连续转动和停止。双极步进仍需四拍换相才能转动，但不需要位置控制、步数校准或 RPM 换算。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `CFG_STEPPER_DRIVER_ENABLED` | `1` | 允许前进；设为 0 可显式禁用。 |
| `CFG_STEPPER_WINDING_PWM_PERCENT` | `10` | 线圈 PWM 占空比，PWM 载波为 20 kHz。 |
| `CFG_STEPPER_COMMUTATION_PERIOD_US` | `50000` | 每 50 ms 推进一次四拍表，即每秒 20 次换相。 |
| `CFG_STEPPER_PHASE_REVERSED` | `0` | 调整实际机械转向。 |

已删除参数确认标志、每输出轴转换相数及 RPM 换算。默认前进可以运行，不再因缺少铭牌拒绝。STOP、失联、接收丢失或发送故障会使两桥进入 coast；相同前进保活或单独调舵不会重置换相节拍。

旧 CMD 字段 `step_speed=60/100` 只作格式兼容，不影响固定低速。状态里的三个 RPM 字段均为 `NA`，`step_on=0/1` 仅表示驱动命令是否运行。OLED 保留原位置和单页布局，打印运行/停止、PWM、舵机、姿态与链路状态。

### 3.2 已知电气条件

用户已确认两组线圈配对，报告电阻约 3 Ω；VM 为约 12 V，来自 45C、3S 航模锂电池。电机没有铭牌，额定相电流仍未知。12 V/3 Ω 得到的约 4 A 是忽略驱动压降的静止满驱估算，不是额定电流或实测运行电流。

本轮采用用户授权的 10% PWM 低功率试运行初值，保留 TB6612 和当前接线。它不等于恒流限制；实际能否持续低速转动及温升需在实物上观察。TB6612 的 1.2 A/通道是绝对最大额定值，3.2 A 仅为 10 ms 单脉冲条件，不能据此开放满驱。[东芝数据手册](https://toshiba.semicon-storage.com/info/TB6612FNG_datasheet_en_20141001.pdf?did=10660&prodName=TB6612FNG)

TB6612 的 STBY 没有 STM32 控制脚，需按当前模块接法保持正常使能。软件 coast 为无励磁停止，不等于切断 VM 供电。

## 4. 舵机、OLED、JY61P 与通信电平

PA6 只输出舵机脉冲。默认以 1 ms/1.5 ms/2 ms 映射 -30°/0°/+30°，但实际机械中位、行程、输入阈值和 5 V 舵机电源的共地方式都待实测。舵机若不能可靠识别 3.3 V 高电平，应使用经验证的单向电平转换，禁止将 5 V 回灌至 PA6。

SSD1306 的 VCC 与 I²C 上拉均为 3.3 V。`ssd1306.c` 通过固定缓冲分块发送，`oled_ui.c` 在主循环中推进刷新。本工程使用原单页 ASCII 状态界面，未移植 `oled-ui-astra`，本轮不改页面布局。

JY61P 的 VCC1 标为 5 V 时，必须额外确认其 SDA/SCL 是否被上拉到 5 V。若是，PB6/PB7 会超出允许输入电平，需要双向 I²C 电平转换或经模块手册确认的上拉方案。还必须确认 I²C 模式、7 位地址、寄存器映射、字节序和校验；不得把 JY61P 的 UART 数据帧照搬为 I²C 寄存器协议。软件会进行 ACK、超时、总线恢复与相邻样本合理性检查，但不能修复错误电平或错误协议。

ESP-01S 与 CH340N 均需交叉收发、3.3 V TTL 逻辑和共地。`STA.link=1` 只说明近期收到有效应用控制帧；没有 ESP 明确上报时，不表示 Wi-Fi、安卓或互联网一定在线。所有外部输入不得超过 3.3 V。

## 本轮资料核对（2026-09-09）

采购资料能确认曾采购 JY61P 成品和 CH340N。现有发票没有明确的 ESP-01S 记录，也没有步进电机额定参数；核心板商品名混列 C8/C6/CH32/GD32，不能单据此确认具体芯片。

`建模/42HS34-FS.STEP` 与装配截图包含 42HS34-FS 设计模型。这仅是核对实物型号的线索，不证明当前电机就是该型号，更不证明额定相电流、步距角或减速比。当前固定低速模式不再依赖该型号、步距角或每转步数，10% PWM 仍是试运行初值。

## 用户提供的 ESP 版本回包

已收到用户通过串口提供的 `AT+GMR` 输出（不是本机自动采集）：

```text
AT version:1.7.4.0(Jul  8 2020 15:53:04)
SDK version:3.0.5-dev(52383f9)
compile time:Aug 28 2020 14:37:33
OK
```

该AT版本匹配当前 `esp_link.c` 的 NONOS 1.7.4 分支。`SDK version` 是底层SDK版本，不用于本工程的AT版本分支选择。先保留现有ESP固件，无需仅为版本匹配而重刷；Flash容量在需要重刷时再核对。

用户随后提供的串口查询为：

```text
AT+UART_CUR?
+UART_CUR:115273,8,1,0,1
OK
```

`115273` 是标称 115200 经分频后的实际波特率，当前驱动允许这一误差；`8,1,0` 为 8N1。最后的 `1` 表示 RTS 流控已开启，与本工程无 RTS/CTS 的接线配置不符。当前驱动会停在 UART 核查阶段并报告错误，不会将 TCP 服务标为就绪。

串口助手保持 115200、8N1、无流控，逐条发送并等待 `OK`：

```text
AT+UART_DEF=115200,8,1,0,0
AT+UART_CUR?
```

预期查询为 `+UART_CUR:115273,8,1,0,0`（约 115200、最后一项为 0）。`UART_DEF` 同时保存上电默认参数；单用 `UART_CUR=` 不会保存，STM32 启动时的 `AT+RST` 会恢复默认参数。设置后可发 `AT+RST`，等 `ready` 再查询以核对持久化结果。依据：[乐鑫 ESP8266 AT 指令集，UART_CUR / UART_DEF](https://www.espressif.com/sites/default/files/4a-esp8266_at_instruction_set_en_v1.5.4_0.pdf)。

用户已提供修正后的查询结果：

```text
AT+UART_CUR?
+UART_CUR:115273,8,1,0,0
OK
```

当前串口配置已匹配驱动要求；AT 版本与当前 UART 参数均已由用户回包确认。尚未记录复位后的复查结果，STM32 到 ESP 的通信和完整 TCP 握手仍需实板验证。
