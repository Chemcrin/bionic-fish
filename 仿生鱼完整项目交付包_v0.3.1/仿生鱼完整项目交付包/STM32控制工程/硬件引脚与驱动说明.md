# 硬件引脚与驱动说明

## 1. 当前接线结论

本版工程只允许一颗两相双极步进电机占用 TB6612 的 A、B 两个 H 桥。必须先将原 N20 电机和抽吸机构从 M2/B01/B02 端物理断开：M1 端连接线圈 A，M2 端连接线圈 B。M1/M2 在这里是同一颗步进电机的两个线圈端，不是两台可并行控制的电机端口。

未经确认的四线电机不能仅用 A 桥驱动，也不能让 B 桥继续接其他负载。若电机不是四线双极类型（例如五线/六线单极、两线执行器或已集成驱动模块），必须停止接线并获得该电机的资料后重新评估；不得套用本工程的双桥换相表。

## 2. 引脚核对

| 功能 | 信号 | STM32F103C8T6 引脚 | 配置/边界 |
| --- | --- | --- | --- |
| 步进线圈 A PWM | `PWMA` | PA0 | TIM2_CH1 PWM，连接 TB6612 A 桥。 |
| 步进线圈 B PWM | `PWMB` | PA1 | TIM2_CH2 PWM，连接 TB6612 B 桥；不是 PA0 的别名，也不是 STEP。 |
| 线圈 A 相位 | `AIN1` / `AIN2` | PB12 / PB13 | 推挽 GPIO，决定 A 桥电流方向/coast。 |
| 线圈 B 相位 | `BIN1` / `BIN2` | PB14 / PB15 | 推挽 GPIO，决定 B 桥电流方向/coast。 |
| 步进线圈 A 输出 | `M1+` / `M1-` | TB6612 A01/A02 | 只能接同一颗步进电机确认后的线圈 A 两端。 |
| 步进线圈 B 输出 | `M2+` / `M2-` | TB6612 B01/B02 | 只能接同一颗步进电机确认后的线圈 B 两端；原 N20 必须断开。 |
| IP65 舵机 | `SIG` | PA6 | TIM3_CH1，50 Hz 脉冲；实际脉宽和 3.3 V 兼容性待测。 |
| SSD1306 | `SCL` / `SDA` | PB8 / PB9 | 独立 GPIO 开漏软件 I²C，外部上拉仅为 3.3 V。 |
| JY61P | `SCL` / `SDA` | PB6 / PB7 | 独立 GPIO 开漏软件 I²C；电平、地址、协议待确认。 |
| ESP-01S | `RXD` / `TXD` | PA2 / PA3 | USART2 交叉收发：PA2→ESP RXD，ESP TXD→PA3。 |
| CH340N | `RX` / `TX` | PB10 / PB11 | USART3 交叉收发：PB10→CH340 RX，CH340 TX→PB11。 |
| 按键 1/2/3 | - | PB0 / PB1 / PA8 | GPIO 输入；当前配置低有效，仍需板上核对。 |
| 运行指示灯 | - | PC13 | GPIO 输出；当前配置低有效，需实板核对。 |
| SWD | SWDIO / SWCLK | PA13 / PA14 | 保留调试，禁止改作业务 GPIO。 |
| 外部晶振 | OSC_IN / OSC_OUT | PD0 / PD1 | HSE 专用，频率/负载电容以实际板卡为准。 |

PB6/PB7、PB8/PB9 在本工程中均由软件 I²C 驱动，不可再同时由 STM32 硬件 I²C 外设接管。ESP 的 `RST/EN/IO0/IO2` 和 JY61P 的 RX/TX 没有给出 STM32 连线，固件不得虚构这些 GPIO/UART。

## 3. TB6612 与两相双极步进

TB6612FNG 是双全桥直流驱动器，不是 STEP/DIR 步进驱动器。当前接法利用它的两个全桥：

```text
TB6612 A01/A02 (M1) ─── 步进线圈 A
TB6612 B01/B02 (M2) ─── 步进线圈 B
```

`motor_control.c` 使用四拍双相通电全步表。每一拍让两组线圈分别获得正向或反向电流；它没有也不需要虚构 STEP/DIR 信号。线圈对接错或某个线圈极性反向时，电机可能抖动、发热、堵转或反向，必须断电后用万用表找出两组线圈，再通过实测线序或 `CFG_STEPPER_PHASE_REVERSED` 修正。

### 3.1 参数确认门禁

下列项目全部为“待实测/待确认”，默认不允许设置为已确认：

| 参数/条件 | 默认值 | 必须确认的内容 |
| --- | --- | --- |
| `CFG_STEPPER_PARAMETERS_CONFIRMED` | `0` | 只有下列参数和接线均有实测记录后才改为 `1`。 |
| `CFG_STEPPER_COMMUTATIONS_PER_OUTPUT_REV` | `0` | 每输出轴一圈所需的完整换相次数，必须综合步距角、换相表和减速比。 |
| `CFG_STEPPER_WINDING_PWM_PERCENT` | `0` | 由线圈额定电流/电压、供电、温升和负载实测得到的安全 PWM，而不是任意默认值。 |
| 步距角/步数每转 | 未知 | “42 型”外形不能推出 1.8°、0.9°或其他值。 |
| 减速比 | 未知 | 必须明确是电机轴还是输出轴 RPM。 |
| 线圈对与极性 | 未知 | 用电阻测量和低功率换相试验确认。 |
| `STBY` | 未知 | 必须确定它被可靠拉高/控制及故障时的安全默认态。 |

在 `CFG_STEPPER_PARAMETERS_CONFIRMED=0`、换相数为 0 或线圈 PWM 为 0 的任一情况下，控制层拒绝运动命令，电机层再次防御性将 A/B 两桥切至 coast。该门禁存在的目的就是避免未知电机被直接通电。

### 3.2 节拍与速度含义

当每个换相表索引移动算一次完整换相时，代码使用：

```text
commutation_period_us = 60,000,000 / (target_rpm × commutations_per_output_rev)
```

因此 60/100 RPM 两档确实有对应的代码路径，但只有填写正确的 `commutations_per_output_rev` 后才有物理意义。它必须表示目标输出轴一整圈所需的换相次数；如存在减速器，减速比已应反映在该参数中。没有编码器、霍尔或外部转速计时，不能验证是否失步，状态帧必须保持 `step_actual=NA`。

### 3.3 电气与失效保护

- TB6612 不提供专用步进恒流斩波。PWM 占空比不能自动保证相电流安全，必须测量额定/启动电流、温升、供电压降和失步边界。
- 两桥换相和安全停止使用 coast（无励磁）状态。软件的 coast 不等价于断开电机供电；`STBY`、驱动默认电平、看门狗或电源关断等硬件失效保护仍需设计并实测。
- 失联或 ESP RX 溢出时，默认 `CFG_STEPPER_STOP_ON_LINK_TIMEOUT=1`，两相释放，避免持续未知相电流。若未来要保持力，必须独立评估发热、姿态和机械安全，不能只是把该配置改为 0。
- `PWMA/PWMB` 的 20 kHz 初值还需依据 TB6612 模块、电机电感、EMI 和热测试调整。绝不应凭声音或是否转动就认定它安全。

## 4. 舵机、OLED、JY61P 与通信电平

PA6 只输出舵机脉冲。默认以 1 ms/1.5 ms/2 ms 映射 -30°/0°/+30°，但实际机械中位、行程、输入阈值和 5 V 舵机电源的共地方式都待实测。舵机若不能可靠识别 3.3 V 高电平，应使用经验证的单向电平转换，禁止将 5 V 回灌至 PA6。

SSD1306 的 VCC 与 I²C 上拉均为 3.3 V。`ssd1306.c` 通过固定缓冲分块发送，`oled_ui.c` 通过服务函数推进页面，不应在中断中刷新整屏。`oled-ui-astra` 上游项目不能原样并入本工程：其上游依赖、引脚占用、阻塞行为和 GPL-3.0 许可证边界都与本工程不同；这里仅保留经重构的非阻塞 UI 思路。

JY61P 的 VCC1 标为 5 V 时，必须额外确认其 SDA/SCL 是否被上拉到 5 V。若是，PB6/PB7 会超出允许输入电平，需要双向 I²C 电平转换或经模块手册确认的上拉方案。还必须确认 I²C 模式、7 位地址、寄存器映射、字节序和校验；不得把 JY61P 的 UART 数据帧照搬为 I²C 寄存器协议。软件会进行 ACK、超时、总线恢复与相邻样本合理性检查，但不能修复错误电平或错误协议。

ESP-01S 与 CH340N 均需交叉收发、3.3 V TTL 逻辑和共地。`STA.link=1` 只说明近期收到有效应用控制帧；没有 ESP 明确上报时，不表示 Wi-Fi、安卓或互联网一定在线。所有外部输入不得超过 3.3 V。
